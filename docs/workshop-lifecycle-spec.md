# أمر المهندس — نظام إدارة دورة حياة طلبات الورشة (النسخة المعدّلة)

## شركة رواسي سما للمقاولات | منصة Zoho Creator (المساعد الذكي Zia)

**توجيه إلى المساعد الذكي Zia في Zoho Creator:** قم ببناء تطبيق متكامل لإدارة دورة حياة طلب عميل الورشة من لحظة وصوله للمعرض حتى إغلاق الطلب نهائياً. التطبيق يجب أن يكون **باللغة العربية بالكامل** وباتجاه **من اليمين إلى اليسار (RTL)**. النظام مُصمَّم ليكون **صارماً**: لا يمكن تجاوز أي مرحلة، وكل انتقال بين مرحلة وأخرى مشروط باكتمال المرحلة السابقة واعتمادها، ويُسجَّل عليه «من نفّذ» و«متى».

## 0. ملخص التعديل (سجل التغييرات — Rev03)

هذه النسخة تعيد هيكلة العلاقة بين أمر البيع والتصنيع وأوامر العمل وطلبات المواد، بناءً على التوجيه التالي:

> «أريد كل **أمر بيع** يكون مرتبطاً بـ **أمر تصنيع واحد** فقط، وداخل أمر التصنيع تكون **أوامر العمل المتعددة**. ولا يجوز أن يكون لأمر بيع أكثر من أمر تصنيع. وبخصوص طلب المواد: يقدر الفني يطلب مواداً لنفس أمر العمل **أكثر من مرة**، لأنه أحياناً لا يطلب كل المواد دفعة واحدة ويحتاج زيادة لاحقاً.»

**ما الذي تغيّر مقارنةً بالنسخة السابقة:**

1. **دمج النموذجين 2 و5:** النموذج الرئيسي السابق «طلبات الإنتاج / أوامر العمل» أصبح اسمه **«أمر التصنيع» (Manufacturing Order)**، وهو الآن **السجل الواحد الوحيد لكل أمر بيع** (علاقة 1:1). أُلغي النموذج المستقل القديم «أوامر التصنيع» (الذي كان يسمح بأكثر من أمر تصنيع لأمر البيع) ودُمج محتواه (تتبّع الإنتاج/المراحل) داخل أوامر العمل.
2. **أوامر العمل أصبحت نموذجاً فرعياً (Subform)** بداخل أمر التصنيع، ويمكن إضافة **أوامر عمل متعددة** داخل أمر التصنيع الواحد. كل صف أمر عمل يحمل **«رقم أمر عمل»** فريد داخل أمر التصنيع.
3. **قاعدة صرامة جديدة:** يُمنع إنشاء أكثر من أمر تصنيع واحد لنفس رقم أمر البيع (رقم أمر البيع فريد ومقفول — السجل الأول يحجز أمر البيع).
4. **طلبات توريد المواد** أصبحت ترتبط بـ **أمر العمل المحدد** (وليس بالطلب ككل فقط)، و**يُسمح صراحةً بإنشاء أكثر من طلب توريد لنفس أمر العمل** لتغطية الطلبات الجزئية والزيادات اللاحقة. أُزيل أي قيد ضمني بطلب واحد لكل أمر عمل.

**الهيكل الجديد باختصار:**

```
أمر البيع (Odoo) ── (1:1) ── أمر التصنيع ──< أوامر العمل (متعددة، Subform)
                                   │                    │
                                   │                    └──< طلبات توريد المواد (متعددة لكل أمر عمل) ──< استلام المواد
                                   ├──< تقارير فحص الجودة (لكل أمر عمل)
                                   └──< سندات التسليم
```

## 3. العلاقات بين النماذج

اربط النماذج كالتالي بحيث يكون **رقم أمر البيع في أودو** ظاهراً ومترابطاً في كل سجل، مع احترام قاعدة **«أمر بيع واحد ← أمر تصنيع واحد»**:

```
العملاء ──< أمر التصنيع (الرئيسي — واحد لكل أمر بيع)
                  │
                  ├── أوامر العمل (Subform داخل أمر التصنيع — متعددة)
                  │        │
                  │        └──< طلبات توريد المواد (متعددة لكل أمر عمل) ──< استلام المواد
                  │
                  ├──< تقارير فحص الجودة (لكل أمر عمل)
                  │
                  └──< سندات التسليم
```

- أمر التصنيع يرتبط بالعميل عبر حقل بحث، ويحجز رقم أمر البيع (فريد، لا يتكرر، مقفول).
- أوامر العمل تعيش **داخل** أمر التصنيع كنموذج فرعي، ولكل أمر عمل **رقم أمر عمل** فريد داخل أمر التصنيع.
- طلبات توريد المواد، الجودة، التسليم: ترتبط بأمر التصنيع، وتجلب رقم أمر البيع تلقائياً. وطلبات المواد والجودة تشير إضافةً إلى **رقم أمر العمل** المعني.

## 4. سير العمل والأتمتة (قواعد الصرامة الأساسية)

نفّذ المنطق التالي بحيث **لا يمكن تجاوز أي مرحلة**:

1. **عند إنشاء أمر تصنيع** ← تحقّق أولاً أنه **لا يوجد أمر تصنيع آخر بنفس رقم أمر البيع**؛ وإن وُجد امنع الحفظ وأظهر رسالة «يوجد أمر تصنيع مسبق لأمر البيع هذا — لا يُسمح بأكثر من أمر تصنيع واحد لكل أمر بيع». ثم تُضبط «حالة الطلب» تلقائياً على **«جديد — بانتظار اعتماد مشرف الورشة»**، ويُرسَل إشعار لمشرف الورشة.
2. **اعتماد المشرف:** إذا اختار «معتمد» ← الحالة تصبح **«معتمد — بانتظار طلب توريد المواد»**. إذا «مرفوض» ← الحالة **«مرفوض من المشرف»** ولا تكمل الدورة. إذا «يحتاج تعديل» ← يعود الطلب لموظف المبيعات.
3. **منع إنشاء طلب توريد مواد** لأي أمر تصنيع حالته ليست «معتمد»، أو لأمر عمل غير موجود ضمنه. **يُسمح بإنشاء عدة طلبات توريد لنفس أمر العمل** (طلب أساسي ثم طلبات زيادة). عند اعتماد أول طلب توريد ← حالة أمر التصنيع تصبح **«بانتظار توريد واستلام المواد»**.
4. **منع إنشاء سند استلام مواد** ما لم يكن طلب التوريد المرتبط معتمداً. عند تسجيل الاستلام بحالة «مكتمل» ← (إذا اكتملت المواد اللازمة لبدء العمل) حالة أمر التصنيع تصبح **«تم استلام المواد — جاهز لبدء التصنيع»**. ملاحظة: بقاء طلبات زيادة لاحقة لا يمنع بدء العمل على أوامر العمل المتوفرة موادها.
5. **بدء التصنيع على مستوى أمر العمل:** يُحدّث الفني «حالة أمر العمل» و«نسبة الإنجاز» داخل كل أمر عمل. بمجرد بدء أول أمر عمل ← حالة أمر التصنيع **«تحت التصنيع»**؛ وعند اكتمال **جميع** أوامر العمل ← **«بانتظار فحص الجودة»**.
6. **منع إنشاء تقرير فحص جودة** لأمر عمل لم يكتمل. إذا كانت النتيجة «اجتاز» لجميع أوامر العمل ← الحالة **«اجتاز الجودة — جاهز للتسليم»**. إذا «لم يجتز» لأي أمر عمل ← الحالة **«أعيد للإنتاج (إعادة عمل)»** ويعاد أمر العمل المعني للقسم المنفِّذ.
7. **منع إنشاء سند تسليم** ما لم تكن نتيجة الجودة «اجتاز» لكامل أوامر العمل. عند تسجيل التسليم ← الحالة **«تم التسليم»**.
8. **منع إغلاق الطلب** ما لم تُحدَّد جميع بنود «تأكيد اكتمال المراحل». عند الإغلاق ← الحالة النهائية **«مغلق»** ولا يُعاد فتحه إلا بصلاحية المدير.
9. **إشعار تلقائي** عند كل انتقال مرحلة إلى المسؤول عن المرحلة التالية.
10. **حقول التدقيق:** فعّل «أُضيف بواسطة / وقت الإضافة / عُدّل بواسطة / وقت التعديل» في كل النماذج واجعلها ظاهرة وغير قابلة للتعديل.

**قيم حقل «حالة الطلب» في أمر التصنيع (بالترتيب):** جديد — بانتظار اعتماد مشرف الورشة / مرفوض من المشرف / معتمد — بانتظار طلب توريد المواد / بانتظار توريد واستلام المواد / تم استلام المواد — جاهز لبدء التصنيع / تحت التصنيع / بانتظار فحص الجودة / أعيد للإنتاج (إعادة عمل) / اجتاز الجودة — جاهز للتسليم / تم التسليم / مغلق.

## 5. الصلاحيات حسب الدور

| الدور | يُنشئ / يعتمد |
| :-- | :-- |
| موظف المبيعات | يُنشئ سجل العميل وأمر التصنيع وأوامر العمل بداخله |
| مشرف الورشة | يعتمد/يرفض أمر التصنيع، يعتمد طلبات توريد المواد، يتابع التصنيع |
| أمين المستودع | يُنشئ سند استلام المواد |
| فني الإنتاج | يحدّث أوامر العمل (الحالة/نسبة الإنجاز)، ويُنشئ طلبات توريد المواد (بما فيها طلبات الزيادة) |
| مفتش الجودة | يُنشئ تقرير فحص الجودة |
| موظف التسليم | يُنشئ سند التسليم |
| المدير / صاحب الصلاحية | يعتمد الإغلاق، صلاحية كاملة، يطّلع على كل التقارير |

كل دور يرى ويحرّر فقط ما يخص مرحلته؛ ولا يستطيع تعديل سجلات المراحل المغلقة.

## 6. التقارير ولوحات المتابعة

1. **لوحة متابعة دورة الحياة** — كل أوامر التصنيع موزّعة على المراحل (عرض Kanban حسب «حالة الطلب»).
2. أوامر التصنيع بانتظار اعتماد المشرف.
3. أوامر العمل تحت التصنيع (عرض على مستوى أمر العمل).
4. أوامر العمل بانتظار فحص الجودة.
5. الطلبات المتأخرة عن موعد التسليم المطلوب.
6. تقرير الطلبات المغلقة مع متوسط مدة دورة الحياة بالأيام.
7. بحث سريع برقم أمر البيع (أودو) يعرض كامل مسار الطلب: أمر التصنيع وأوامر عمله وطلبات المواد والجودة والتسليم.
8. تقرير طلبات المواد لكل أمر عمل (يُظهر الطلب الأساسي وطلبات الزيادة وإجمالي ما طُلب وما وُرّد).

## 7. ملخص قواعد الصرامة المطلوبة

- رقم أمر البيع في أودو **فريد ومقفول** ومرجع وحيد لكل النظام.
- **أمر بيع واحد ← أمر تصنيع واحد فقط:** يُمنع إنشاء أكثر من أمر تصنيع لنفس رقم أمر البيع.
- **أوامر العمل متعددة داخل أمر التصنيع الواحد** (نموذج فرعي)، ولكل أمر عمل رقمه الفريد.
- **طلبات المواد متعددة لكل أمر عمل:** يُسمح للفني بطلب مواد لنفس أمر العمل أكثر من مرة (طلب أساسي + طلبات زيادة).
- **لا يمكن تخطي أي مرحلة** — كل نموذج تابع لا يُفتح إلا بعد اكتمال واعتماد سابقه.
- كل اعتماد ورفض يُسجَّل عليه **المستخدم والتاريخ والوقت والتوقيع**.
- **سبب الرفض إلزامي** ولا يُحفظ الرفض بدونه.
- المرفقات إلزامية في النقاط الحرجة: المخططات عند الفتح، فاتورة المورد عند الاستلام، صور الفحص، سند التسليم الموقّع.
- الكميات يجب أن تكون أكبر من صفر.
- لا تُغلق الدورة إلا بتأكيد اكتمال جميع المراحل واعتماد المدير.

**انتهى أمر المهندس (Rev03).** نفّذ هذا التطبيق بكامل النماذج والحقول والعلاقات وسير العمل وقواعد الصرامة كما هو موضح أعلاه.
