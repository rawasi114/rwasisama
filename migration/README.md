# دليل ترحيل البيانات الآمن — رواسي سما

ترحيل المستخدمين والبيانات الصغيرة (< 10 مستخدمين) إلى الفرع الجديد عبر **الاستيراد
القياسي من واجهة أودو**، دون سكربتات هشّة ودون المساس بكلمات مرور الإنتاج.

## مبدأ السلامة
- **لا تُنقل كلمات المرور أبداً.** يُنشأ المستخدم بلا كلمة مرور، ثم يضبط كل مستخدم
  كلمته بنفسه عبر رابط «إعادة تعيين كلمة المرور» الذي يصله بالبريد.
- **لا تلمس بيئة الإنتاج (`rawasisama`).** التصدير من الإنتاج يتم يدوياً بصلاحيات
  المسؤول، والاستيراد يتم في بيئة الستيج/التطوير فقط.

## الخطوات

### 1) المستخدمون (`migration/users_template.csv`)
1. عبّئ الملف بأسماء المستخدمين وبريدهم ومجموعة الصلاحية المناسبة.
2. في أودو: **الإعدادات ← المستخدمون ← استيراد**، وارفع الملف.
3. عمود `groups_id/id` يقبل المعرّف الخارجي للمجموعة، مثل:
   - `rawasi_construction.group_site_engineer` — مهندس موقع
   - `rawasi_construction.group_technical_office` — مكتب فني
   - `rawasi_construction.group_project_manager` — مدير مشاريع
   - `rawasi_base.group_rawasi_accountant` — محاسب
   - `rawasi_base.group_rawasi_procurement` — مشتريات
   - `rawasi_base.group_rawasi_admin` — مسؤول النظام
4. بعد الاستيراد فعّل «إرسال دعوة بالبريد» ليضبط كل مستخدم كلمته بنفسه.

### 2) مقاولو الباطن (`migration/subcontractors_template.csv`)
استورد عبر **المقاولات ← مقاولو الباطن ← استيراد**.

### 3) البنود المرجعية (`migration/reference_items_template.csv`)
استورد عبر **المقاولات ← الكتالوج ← البنود المرجعية ← استيراد**.
عمودا `lcgpa_code_id/id` و`sbc_code_id/id` اختياريان (المعرّف الخارجي للرمز).

## ملاحظات
- القيم بين `xxxxxx` نماذج توضيحية — استبدلها ببيانات حقيقية قبل الاستيراد.
- وحدات القياس تستخدم معرّفات أودو القياسية (`uom.product_uom_*`).
- لأي حجم بيانات أكبر، كرّر النمط نفسه بإضافة صفوف — لا حاجة لسكربتات ترحيل.
